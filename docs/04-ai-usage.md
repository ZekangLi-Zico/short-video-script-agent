# 04 · AI 辅助范围、个人贡献与验证

## 使用方式

本项目在 Codex 辅助下完成。AI 参与需求拆解、技术方案、程序实现、测试设计、运行调试、文档和提交材料整理。仓库中的运行证据由实际执行程序产生，没有由模型手写成功日志替代运行。

开发助手与被测试的 Agent 模型是两个角色：前者辅助构建项目；后者通过 `src/providers.py` 接收业务状态并选择下一动作。Mock 是固定测试桩，与真实模型证据分开。

## 当前可核实的候选人贡献

- 提供完整笔试要求与四道题目材料。
- 在比较后选择第 4 题“短视频脚本 Agent”。
- 确定交付范围：代码、测试和提交文档。
- 提出人工测试需求，要求增加可填写需求、查看脚本和执行过程的简单网页。

当前版本的实现、修改与自动验证由 AI 工具执行。本记录不声称候选人已独立手写全部代码，或已亲自完成尚无记录的验证。候选人后续若实际修改代码或运行验证，应在此追加真实改动、命令与结果。

## AI 生成内容的核验与修正

| 内容 | 验证方式 | 发生的调整 |
|---|---|---|
| 模型动作与完成状态 | 有限步循环与提前完成反例测试 | 完成必须绑定当前稿件哈希及两项通过检查 |
| 产品事实和引用 | 引用原文、来源变化、伪造文本测试 | 采用逐字引用块，拦截“真实 ID + 虚构句子” |
| 超时后的修改 | 38 秒旧稿验收 | 要求先有失败估时观察，再改稿、再检查 |
| 环境接入 | 实际 Codex 调用和失败记录 | 从旧 PATH CLI 改用桌面自带版本 |
| 测试与报告 | 真实 unittest、批量验收、JSON 产物 | 所有次数和结果以运行文件为准 |

## 可核验入口

- `src/providers.py`：提交给业务模型的系统提示和动作协议。
- `src/mock.py`：明确标注的离线桩。
- `examples/live/`：真实调用返回、工具结果和后续动作。
- `examples/mock/`：离线示例，不作真实模型能力证明。
- `examples/test-results/`：自动测试日志和汇总。

不提交真实密钥、账号登录文件、私有资料或模型内部思维链。Trace 中的 decision_basis 是简短的动作依据。

## 个人复验建议

网页扩展的代码、13 项新增自动测试及浏览器操作同样由 AI 开发助手完成；已实际操作正常、缺信息、故障及真实模型超时修订，并修正历史恢复和状态标注。证据见 `examples/ui/`，不将这些点击记为候选人个人操作。

候选人可以实际运行 `python -m scripts.run_tests`，修改 `data/materials.json` 中一条事实后观察旧稿失效，或运行 `over_duration` 观察模型修订。只有实际做过后，再把自己的解释和记录追加到这份文档。
