# 网页人工测试指南

当前v7.3.1：页面顶部和新运行显示v7.3.1-submission。场景创作的新稿按“时间（镜内）／动作与画面／对白与声音”阅读，每句标明说话者；纯动作段显示无对白，现场声单独列出。下载脚本保留同样的时间和动作。历史v2仍显示原有整镜说明，不自动补编动作；要获得新编排，可载入原需求重新生成，旧记录仍保留。当前产品、超时、无素材和工具故障证据见[验收索引](../examples/current/evaluation.md)。

继承的“连读台词与旁白”及TXT下载只包含实际朗读文字；动作、说话者标签和屏幕文字不混入其中。镜内时间是相对本镜开头，左侧是整条视频时间；均为脚本估算，不是已完成口型同步。

继承的声画功能：脚本预览区分旁白、屏幕文字和同步字幕。来源标签可查看支持文案的原句，文案可以是准确改写或翻译。双语实测见 `evaluations/realistic-50-v6-20261105/runs/V22/`。执行过程显示模型选择审核后实际进行的本地预检查、独立审核与有限恢复阶段，各项工具参数与返回都能展开查看。

“镜头目的”和“审稿备注”属于创作者的说明，不进入视频、不计时、不代替公开功能介绍。旧稿可不含这些新字段，仍可读取；当前新稿没有备注时为空字符串。

## 打开页面

Windows 双击项目根目录 `启动网页.cmd`。也可以在 PowerShell 运行 ` .\run.ps1 -Mode web`，然后打开 http://127.0.0.1:8765/ 。服务已启动时，再次运行会打开已有页面。关闭首次启动的终端或按 Ctrl+C 可停止服务；需要时重新双击启动。

跨平台命令：`python -m src.web --open`，需要 Python 3.11+。如果 8765 被其他程序占用，使用 `python -m src.web --port 8766 --open`。

修改代码后需重启服务加载新版。历史v7正式测试使用8842–8845端口；当前v7.2故障复测使用8765。保留的旧版服务不会自动变成新版。Codex遇到超时、服务繁忙或流中断时，每次调用最多重试一次，整次任务最多恢复两次；页面区分决策重试与审核重试，失败尝试也保存脱敏诊断。审核恢复失败会直接保存草稿并结束。当前调用结束前取消不会立即终止正在进行的模型请求。

## 第一次操作

1. 选择“正常生成”，检查主题、受众、平台、目标时长、风格。
2. 先选“离线演练 · Mock”熟悉页面。再切换“真实模型 · Codex”验证模型决策；本机需要已登录、可调用模型的 Codex。真实运行会消耗账号额度，通常需要一到数分钟。
3. 点击“生成并检查”。执行过程中可以看当前草稿及各步观察；展开“查看参数与返回结果”可看原始工具输入和输出。
4. 结束后切换“脚本预览”。核对总时长、每个分镜的旁白、来源标记与风险。点击“原始结果”可核对最终状态。
5. 下载脚本、Trace 或 JSON，或直接查看 `outputs/web/<运行ID>/`。

v4 增加“下载检查点”：任务运行中就可下载最后写入的草稿、检查结果和 Trace。它标记为 `in_progress`，不是最终成功结果。最终文件保存完成后，才显示完整下载入口。出现异常时，若检查点已写入，该入口仍可用。

页面的来源 ID 表示稿件声称引用的素材；只有规则检查通过，才说明当前稿通过本项目的来源校验。未通过检查的稿件会标为草稿，不能当作验收成功。

修复版增加“需求核对”：查看各项原始要求是否满足，以及具体证据/遗漏。其结论来自同后端模型的新上下文，页面标注“仍需人工确认”。旧历史记录没有这项检查，会显示“未执行”，原状态不被改写。最终说明保留模型对删改、风险和资料缺口的解释。

## 建议亲手执行的场景

| 载入的场景 | 重点看什么 | 合理结果 |
|---|---|---|
| 正常生成 | 引用是否对应素材，估时是否不超过 30 秒 | 检查通过，有分镜和实际工具记录 |
| 缺少关键信息 | 目标时长留空后再运行 | 提示补充目标时长；不调用模型、不假装完成 |
| 没有产品素材 | 检索返回空后下一步怎么选 | 补查或请求补充，不编造产品事实 |
| 工具持续失败 | 展开检索返回，检查真实错误 | 明确未完成，不把失败记为成功 |
| 一次故障后恢复 | 第一次失败后的动作及成功观察 | 在有限步内恢复；保存前面实际记录 |
| 38 秒旧稿修订 | 先有 38 秒失败估时，后有写稿和复检 | 新稿不超过 30 秒且规则通过；也应保留中间失败 |
| 无依据宣传纠错 | 旧稿的“效率提升80%”是否被发现 | 删除无依据宣传并重新检查 |
| 无法满足的时长 | 1 秒小于最短镜头 2 秒 | 明确无法满足，不擅自改用户上限 |

Mock 只验证流程，行为是固定的。真实模型可能选择不同路径；核对实际观察与状态，不要求和示例逐字一致。

## 自己修改需求

表单可以直接改主题、受众、风格和时长。主题应围绕当前提供的“剪影练习版”素材；在“查看可用素材”里查看事实。“场景创作”允许原创标题、拍摄场景和连接语，但不允许编造产品能力。“严格引用”保留原版批准表达，便于对照。

时长要求选“不超过目标秒数”时允许较短脚本；选“接近目标”时预计时长应在目标的90%–100%。该区间是项目明确的产品约定，原题没有规定90%这个数值。目标时长不应用重复文案或空镜补齐。

新需求请先点“重置”，确认旧稿输入框是否应为空，避免在历史恢复后不经意带入旧稿。历史记录会保留原来的创作方式与时长语义。

“需求覆盖核对”中可展开逐项表达审核；已核对引用不等于所有创意文案都已核对。执行过程中会显示“尚未完成表达审核”等状态。修订步骤显示实际改变字段和保留数量，不只显示模型声称修改了什么。

“测试设置与旧稿”可注入工具故障或粘贴结构化旧稿。最方便的方法是先载入超时场景，再改其中的 `hold_seconds`，观察估时与下一动作是否变化。不要只看最后一句“成功”，要核对执行过程里的时长、规则和需求三项检查都针对当前稿。

选“最近运行”会同时还原原始需求和结果，可在此基础上修改重跑。刷新可重新显示正在运行的任务；服务重启会恢复最近 32 条已保存记录，但不会自动续跑中断任务。点击“停止后续步骤”后，会等待当前模型调用结束再停止，已有记录仍保存。

v4 服务重启还会把已中断任务的最后有效检查点恢复为“未完成”，保留恢复原因，不会标成成功或重新调用模型。仍存活进程持有的任务会跳过恢复。磁盘持续不可写、首个检查点写入前退出、当前尚未返回的模型步骤仍可能没有完整记录；这不是自动续跑或多进程任务调度系统。

需求审核现在会看到当前稿逐镜估时和总时长。`hold_seconds=0` 表示未另设最短停留，不表示镜头实际为零秒；页面里的预计镜头时长才是估时工具结果。该修复不保证模型每次语义判断都正确，也不替代成片实测。实测结果及保留问题见 [v4有限修复报告](10-finite-v4-report.md)。

若要换成自己的产品资料，需要修改 `data/materials.json` 和相应品牌规则，并通过 CLI 或代码调整产品选择；本页面尚无素材上传/编辑功能。
