# 网页人工测试指南

## 打开页面

Windows 双击项目根目录 `启动网页.cmd`。也可以在 PowerShell 运行 ` .\run.ps1 -Mode web`，然后打开 http://127.0.0.1:8765/ 。服务已启动时，再次运行会打开已有页面。关闭首次启动的终端或按 Ctrl+C 可停止服务；需要时重新双击启动。

跨平台命令：`python -m src.web --open`，需要 Python 3.11+。如果 8765 被其他程序占用，使用 `python -m src.web --port 8766 --open`。

## 第一次操作

1. 选择“正常生成”，检查主题、受众、平台、目标时长、风格。
2. 先选“离线演练 · Mock”熟悉页面。再切换“真实模型 · Codex”验证模型决策；本机需要已登录、可调用模型的 Codex。真实运行会消耗账号额度，通常需要一到数分钟。
3. 点击“生成并检查”。执行过程中可以看当前草稿及各步观察；展开“查看参数与返回结果”可看原始工具输入和输出。
4. 结束后切换“脚本预览”。核对总时长、每个分镜的旁白、来源标记与风险。点击“原始结果”可核对最终状态。
5. 下载脚本、Trace 或 JSON，或直接查看 `outputs/web/<运行ID>/`。

页面的来源 ID 表示稿件声称引用的素材；只有规则检查通过，才说明当前稿通过本项目的来源校验。未通过检查的稿件会标为草稿，不能当作验收成功。

## 建议亲手执行的场景

| 载入的场景 | 重点看什么 | 合理结果 |
|---|---|---|
| 正常生成 | 引用是否对应素材，估时是否不超过 30 秒 | 检查通过，有分镜和实际工具记录 |
| 缺少关键信息 | 目标时长留空后再运行 | 提示补充目标时长；不调用模型、不假装完成 |
| 没有产品素材 | 检索返回空后下一步怎么选 | 补查或请求补充，不编造产品事实 |
| 工具持续失败 | 展开检索返回，检查真实错误 | 明确未完成，不把失败记为成功 |
| 一次故障后恢复 | 第一次失败后的动作及成功观察 | 在有限步内恢复；保存前面实际记录 |
| 38 秒旧稿修订 | 先有 38 秒失败估时，后有写稿和复检 | 新稿不超过 30 秒且规则通过；也应保留中间失败 |
| 无依据宣传纠错 | 旧稿的“效率提升80%”是否被发现 | 删除无依据宣传并重新检查 |
| 无法满足的时长 | 1 秒小于最短镜头 2 秒 | 明确无法满足，不擅自改用户上限 |

Mock 只验证流程，行为是固定的。真实模型可能选择不同路径；核对实际观察与状态，不要求和示例逐字一致。

## 自己修改需求

表单可以直接改主题、受众、风格和时长。主题应围绕当前提供的“剪影练习版”素材；在“查看可用素材”里查看事实。项目采用逐字引用事实块和批准连接语，不是任意主题的无限制文案生成器。

“测试设置与旧稿”可注入工具故障或粘贴结构化旧稿。最方便的方法是先载入超时场景，再改其中的 `hold_seconds`，观察估时与下一动作是否变化。不要只看最后一句“成功”，要核对执行过程里的两个检查都针对当前稿。

选“最近运行”会同时还原原始需求和结果，可在此基础上修改重跑。刷新可重新显示正在运行的任务；服务重启会恢复最近 32 条已保存记录，但不会自动续跑中断任务。点击“停止后续步骤”后，会等待当前模型调用结束再停止，已有记录仍保存。

若要换成自己的产品资料，需要修改 `data/materials.json` 和相应品牌规则，并通过 CLI 或代码调整产品选择；本页面尚无素材上传/编辑功能。
