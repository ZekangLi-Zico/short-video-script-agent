# v5 · 自然表达、声画安排与可拍分镜

这轮目标是提高实际交付效果：已有事实能够自然改写或翻译；旁白与屏幕文字有明确的播放关系；镜头通过具体动作讲清信息。代码仍是单 Agent、Python 标准库和最多 12 步的模型工具循环。

## 三项实现

|优化|原来的阻碍|现在的行为|对应原题价值|
|---|---|---|---|
|有依据的改写、压缩、翻译|要求产品事实逐字引用，英文或短卡片需求可能被阻断|新稿保存文案和来源原句；核对来源身份，再核对原文是否支持改写|事实可追溯，同时能完成更多实际表达需求|
|旁白、屏幕文字、节拍|文字统一串行计算，静音卡、双语同步关系靠备注解释|voice/screen/both 明确用途，同拍同步、不同拍依次；显示每拍与镜头末尾保持时间|时长检查更贴近脚本的实际安排，也更便于剪辑师使用|
|具体可拍的分镜|功能说明容易成为独立卡片，镜头仅作背景|每镜写明信息用途、主体动作和前后变化，引导用演示承载功能|提高分镜可执行性，增强有效修订的价值|

公开稿件的事实检查、需求检查和时长检查仍绑定同一版本。普通生活情节可直接创作，不需要向用户索要产品证明；已有事实的准确翻译也不再要求用户提供核准译文。只在实际缺少必需事实或关键输入时追问。

旧格式与 strict 模式保持原有规则。新稿 `format_version=2` 才使用新的表达和估时路径；50份 v4.1 已保存记录在新代码下复算无差异。没有修改过去的输出来制造改善。

## 尚未解决的实际问题

1. **标题个性化退步。** 新版22份稿件复用四个示例标题之一，旧版仅2份；部分开头和结尾也偏泛。V32把具体错字示例写泛，教学信息弱于旧版。这是当前最明确的内容优化方向。
2. **自然模型超时仍存在。** V05/V28检索后写稿超时，未生成脚本，诊断和检查点均完整保存；没有重跑覆盖。本轮不能宣称稳定性提高。
3. **仍有可避免的返工。** V25首稿多讲手动编辑，审核后改正，响应7→12；V07/V46各有一次空文案块格式错误后恢复。结构化输出与范围遵循还不完全稳定。
4. **地道杭州话没有完成。** V24仍请求口语参考。资料库没有收费、导出、隐私或其他产品资料时，不能靠改写补出事实；新版已尽量只问完成任务所需的最少信息。
5. **时间仍为估计。** 已区分同步与串行、英文词和汉字，但没有用真实配音校准，也没有生成成片。该边界符合原题脚本任务，不能称为实测成片时长。

测试期间不再改应用，避免将不同版本混成一次50组结论。后续优先处理标题/结尾的场景针对性和调用耗时，再用相同输入检验；不靠放宽事实要求或去掉审核来提高数字。

## 对笔试评审的价值

原题明确看重有效修订与事实可追溯。现在评审既能看到有依据的改写、翻译、压缩实际解决了需求，也能逐步核对工具反馈怎样影响下一步；分镜用途、声画节拍和可见动作让结果更容易实际使用。50次完整记录、失败保留、旧版对照和118项自动测试提供可复核依据。没有为了展示框架而加入多Agent或生产部署。
