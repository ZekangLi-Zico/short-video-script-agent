旧版保留于 `archives/v2-limited-20261104/project.zip` 和 `current-source.zip`，根目录旧交付ZIP未覆盖。`freeze.json`保存1597个旧证据文件的哈希。原始50次网页测试、有限修复各阶段的成功和失败都继续保留。

同一新需求N01–N04在旧版均因固定标题、画面或英文表达限制而needs_input。新版是否真正符合需求另行逐稿评阅，不能仅由completed判断。N03首轮就暴露了“事实有依据但超出用户限定范围”的问题。

## 本轮暴露的问题与修复

1. **审核结果结构异常可能中断证据保存。** 独立代码审阅发现pacing.verdict为数组/对象会触发TypeError。公开Agent失败测试先复现，再加类型校验；失败现在记录为审核失败，不能完成。
2. **网页提示过早宣称连接语已检查。** 创作模式的本地引用检查不证明连接语语义正确，已改为匹配逐项审核结果显示待审、缺少依据或模型已核对。
3. **N03的排他范围误判。** 首轮要求“只讲添加字幕”却加入手动编辑，审核也放行。没有修改输入，原结果保留；写稿及审核提示明确“只/仅X”不允许追加相邻功能，再复测N03与多功能正例N02。提示修正仍不是语义正确性的形式证明。

## 保留的问题与未扩展范围

- 语义审核可能误判，和写稿使用同一后端的新上下文，可能相关犯错。严格模式能机械验证批准原文，creative模式不能保证所有自由表达均无误。
- **节奏审核仍有具体误判：** N03修复复测中，审核把hold_seconds的最短停留误当实际镜头时长，忽略工具会取旁白估时的更大值，导致额外改稿。最终输出符合上限，但这次延长不能证明节奏更好。本轮未再扩展审核上下文协议，后续应把实际逐镜估时直接提供给审核。
- 时长为文本/阅读与hold估算，无TTS或真实成片校准；旁白和屏幕文字尚未结构化分轨，英语混合事实卡尤其需要人工计时。
- 目标时长和节奏审核可能增加修订次数；T43刚好12步完成，复杂需求仍可能step_limit。没有为提高样本成绩临时放宽上限。
- 关键词检索、最多8镜头、合成产品素材保持不变。没有引入业务素材上传、企业知识库、跨会话续跑或自动剪辑。
- 真实API后端仅有契约测试，本轮真实调用使用已登录Codex。没有优化启动开销、耗时或成本；本轮并行复测不能当作延迟基准。
- 网页历史会还原旧稿，另起需求需先重置；一次测试误带历史旧稿已单独保存说明，未混入冻结对照。
- 一次HTTP访问控制测试发生WinError10053连接中断，根因未确定；同一测试和后续全套81项复测通过，保留该次失败记录。
- GitHub URL、当前版本最终commit SHA、私有仓库评审权限和候选人亲自复验记录仍需完成；本轮没有上传或交卷。
