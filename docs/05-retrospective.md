# 05 · 实现复盘与下一步

这是一份项目实现过程记录，由 AI 辅助整理，不冒充候选人的个人学习经历。

## 最难的问题

**如何证明脚本有依据，而不仅是附带来源 ID。** 如果模型写“效率提升 80%”并引用真实存在的 P01，简单检查 ID 存在会错误放行。本项目将公开文案拆成引用事实与允许的连接语，事实必须逐字对应已检索原文；标题和画面指令也要遵守批准列表。这是一个有明确限制、但可以机械验证的取舍。

**如何证明改稿后的结果真的重新检查。** 初稿已通过时长检查，并不代表修改后仍然通过。程序在每次更新稿件后清空旧检查，并用内容哈希绑定检查版本，提前完成会成为模型下一步看到的错误观察。

**如何获得真实模型证据。** 离线 Mock 能证明代码流程，却不能证明动态决策。本次保留 Mock 作为无凭证入口，同时通过已登录的 Codex CLI 运行真实模型。遇到旧 CLI 不兼容时保留失败记录，改用现有新版运行程序，不把失败替换为虚构成功。

## 工程收获

- Agent 的效果需要从“观察→后续动作”的记录中评估，只有漂亮的最终脚本不够。
- 负向场景中明确未完成也是正确结果，状态必须与工具证据一致。
- 模型生成负责选择、组织和修订；输入约束、计时和完成门禁由确定性代码保证。
- 证据要同时保留输入、实际输出、工具记录、数据版本和限制，方便复核。

本次按题目优先完成 CLI 核心链路、测试和文档。未实现真实视频生成、部署、界面、多 Agent、持久多轮会话；这些不属于本题必需范围。API 传输后端完成契约测试，但无真实 Key 联调。GitHub 远程上传与私有仓库评审授权尚待账户登录后处理。
