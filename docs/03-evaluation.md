# 03 · 测试、实际结果与限制

## 证据分层

1. [自动测试记录](../examples/test-results/unittest.txt) 与 [机器摘要](../examples/test-results/summary.json)：离线单元、集成与适配器契约验证。
2. [Mock 验收](../examples/mock/evaluation.md)：八个场景，验证程序流程；不证明模型决策。
3. [真实模型验收](../examples/live/evaluation.md)：使用已登录 Codex CLI 实际调用模型，保留每次动作与工具观察。缺必填信息路径为前置校验，未调用模型。
4. [初次 CLI 失败记录](../examples/attempts/codex_sandbox/normal/trace.jsonl)：保留环境接入失败，不把它算成功运行。

当前量化结果以以上机器产物为准；不要把“负向用例验收通过”解释为“该业务任务完成”。

本次结果：**45 项自动测试通过，8/8 离线验收通过，8/8 真实后端场景符合预期，16/16 运行产物通过本地工具复算。** 真实后端的缺信息场景为 0 次模型调用，其余 7 种场景含实际模型响应。

最新正常生成是 5 个分镜、预计 **27 秒**；超时场景实际记录为 **38 秒→模型修订→25 秒**，修改后的来源与规则检查通过。一次工具故障后的恢复路径与持续失败停止路径均有实际记录。

运行 `python -m scripts.verify_evidence` 可复算已保存的本地工具观察、稿件哈希与最终检查状态，结果见 `examples/evidence-audit.json`。它验证证据内部一致性，不会重新调用或独立认证远端模型。

## 测试预期

| 场景 | 预期行为 |
|---|---|
| normal | 有来源脚本、当前时长和规则检查均通过后 completed |
| missing_information | 列出缺失的 target_seconds，返回 needs_input |
| no_material | 面对空检索结果补查或请求补充，不编造素材 |
| tool_failure | 实际触发持续故障并 blocked/step_limit，不伪造成功 |
| recoverable_failure | 观察第一次故障后调整动作，恢复并完成 |
| over_duration | 对 38 秒旧稿先估时，观察超时后改稿，再检查 |
| rule_revision | 检查旧稿中的无依据效果宣传，观察风险后修订 |
| impossible_duration | 1 秒上限无法满足最短镜头约束，明确未完成 |

## 如何阅读动态决策证据

建议从 `examples/live/over_duration/trace.jsonl` 和 `examples/live/tool_failure/trace.jsonl` 开始。每行包含实际动作、工具参数、实际观察和简短依据；下一行就是模型观察该结果后选择的动作。

正常路径与超时修订路径的差异应来自不同检查结果。批量验收会检查超时路径确实出现 `estimate_duration` 返回 passed=false，之后再出现 `write_script`；不会把直接替换旧稿当作“根据工具反馈修订”的证据。

规则纠错也检查先出现不通过的 `check_rules`，再出现改稿。故障场景检查 Trace 确实包含注入的工具错误。

## 自动测试关注点

除必需场景外，测试还覆盖：

- 真实来源 ID 搭配编造文本、未检索来源、资料更新、无事实稿件；
- 在标题、镜头描述或“创意文案”中夹带产品断言；
- 修改稿件后复用旧检查、工具失败后强行完成、未知动作；
- 零/负/布尔/非有限时长、最大步数、非法素材格式、重复 ID；
- CLI 退出状态、输出文件写入失败；
- Responses 与 Chat 接口结构、HTTP 失败脱敏、模型超时、无密钥不降级；
- Codex 意外调用额外工具时拒绝结果，禁止使用它绕过本地工具闭环。

## 已遇到的问题与处理

PATH 中 Codex CLI 0.152.1 无法调用配置的 gpt-6-astra，服务返回“需要更新版本”。改为优先使用桌面应用提供的 CLI 0.166.0-alpha.5.1，后续真实运行成功。没有更改用户的默认模型配置，也没有升级全局 CLI。

测试临时目录在本机沙盒内不可写，改为仓库 `.runtime/tests/` 下的隔离临时目录，测试结束自动清理。API 错误契约测试曾先触发本机 SSL 初始化错误，调整 Mock 到传输入口，使离线契约测试不依赖本机证书环境；这不构成真实 API 联调证据。

首轮正常脚本预计 12.8 秒，超时稿修订后 7.3 秒，均满足 30 秒上限，但节奏偏短。随后补充“尽量接近目标时长、保留有用镜头”的提示，重跑这两个真实场景。原记录保留在 `examples/iterations/before_pacing/`；最新结果见 `examples/live/`，其他验收场景没有为凑数重复调用。

## 已知限制

- API 后端本次没有真实 Key，只有离线契约测试；真实模型验证使用 Codex CLI。
- 真实模型场景是小规模单次抽样，不是成功率基准，不保证所有模型、所有输入都稳定成功。
- 模型可能用不同顺序调用工具；以最终检查和观察后的行为为准，不要求逐字复制 Trace。
- 文案采用受控组合，事实要逐字引用，牺牲自由改写；素材检索是关键词匹配，没有语义向量索引。
- 时长未经配音或成片测量；数字和不同语速可能带来估算误差。
- 只验证是否忠实于输入资料，不能证明合成资料对应真实产品，更不能替代业务素材审核。
- 未实现多轮会话恢复、UI、部署或视频生成。needs_input 后可以补齐字段重新运行。
