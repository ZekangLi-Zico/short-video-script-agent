# 逐段动作与对白编排

用户已确认上一轮展示的“时间／人物动作与画面／对白”方案。目标是让脚本能看出怎么演、怎么拍，而非只把台词放大。保留版本和全部实验，不改原题完成条件，不引入新框架。

方案选择：仅放大整镜灰字仍不能把动作对应到对白；解析自由文本推断时间和说话者会伪造细节；采用模型一次生成结构化动作段，并沿用现有估时与审核。用户批准的是三列表达形式，以下字段与兼容方案由实现者确定。

- 创作模式新稿 format_version=3。每镜保留 visual 交代场景；staging 按 beat 编排 action、camera、sound、min_seconds。每个有声块增加 speaker。镜头可有无对白的动作段，给出实际最低停留；正常对白段不强制额外动作或运镜。
- 每段预计时长取声音、屏幕文字和动作最低停留的较大值，随后顺序累加。动作描述、说话者、机位和现场声不计入配音文字。它们是创作安排，不是已生成视频或完成口型同步。
- 每个文案段必须对应一个动作段，防止时间无归属。普通停顿和镜头设计无需新的资料证明；改变人物身份、关键事件、受伤状态等仍交给原有语义审核。新增动作内容纳入现有审核，不增加模型调用阶段。
- 网页按镜头显示三列，动作与对白同等可读；显示人物名而非统一“配音”。下载Markdown使用同一投影。删去“同拍声画同步”，只有实际存在屏幕文字时才提示字幕保留。
- 历史v1/v2原记录不改，v2仍显示原有整镜画面与分段台词，不为它补造精确动作。strict仍使用v2生成；全部旧格式继续复算。
- 本轮只做针对性真实网页复测：原样重跑用户同乡楼道片段，以及一条包含明显动作、无对白间隙的现实创作需求。提前冻结输入，保留每次结果。不要启动20/50次批量实验。
