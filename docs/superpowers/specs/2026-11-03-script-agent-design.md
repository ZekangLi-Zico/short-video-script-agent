# 第 4 题：设计与验收约束

依据：用户提供的笔试截图及其选择第 4 题、要求完成代码/测试/提交文档的指令。

目标：给定主题、受众、平台、时长、风格与合成产品资料，生成带事实来源、分镜和预计时长的可编辑脚本。模型观察工具返回，自主选择补查、改稿、复检或结束。

采用 Python CLI + 原生决策循环（实现者选择），不依赖外部 Agent 框架。备选 HTTP 服务会增加部署工作；Notebook 的批量测试和退出状态不如 CLI 直接。三种入口题目均允许，选 CLI。

业务工具为真实本地函数：检索、时长估算、规则检查。提供真实模型后端与明确标注的离线 Mock；Mock 不用作真实模型决策证据。资料为合成，不声称是小影实际产品功能。

对外产品文案采用可审计的引用块：事实块必须逐字对应已检索事实；非事实连接语、标题和镜头指令来自可扩展的品牌允许表。模型选择组合、镜头顺序和停留时间。此取舍牺牲自由改写，换取小型项目内可机械验证的事实边界；不声称通用语义事实核验。

每一稿有内容哈希；改稿后清空检查结果。完成必须同时满足：有来源事实、规则通过、预计时长不超过上限、两个检查针对同一稿。未知动作和异常返回结构化观察。达到最大步数明确未完成。

验收：正常、缺关键信息、无素材、工具失败、超时长修订/失败；补充规则风险、来源变化、无效模型输出、提前完成和步数上限。保留至少三组实际运行产物与两条不同路径。

仅生成脚本，不生产或发布视频。提交所需 GitHub URL 和评审权限由最终上传环节确定；当前没有 GitHub 登录，不虚构仓库或候选人个人贡献。
