# 五分钟评审路线与候选人复验

本页帮助评审快速定位证据，也供候选人亲自理解和复验。它不是候选人已经完成学习或独立开发的证明；AI 辅助范围见 `04-ai-usage.md`。

## 五分钟看什么

1. 打开[当前四类验收](../examples/current/evaluation.md)，先看产品脚本，再看超时输入、实际修改和Trace。
2. 看无素材与工具故障的返回：是否给出实际缺口或失败原因，是否避免冒充成稿。受控工具故障有明确标签。
3. 运行网页，确认顶部v7.3.1-submission，查看动作、说话者、连续旁白与来源。需要看改动前后，可读[v7.3动作对照](../evaluations/staging-v7.3-20261106/README.md)。
4. 执行 `python -m scripts.verify_evidence --group current` 复算当前材料，再看[本轮报告](../evaluations/submission-v7.3.1-20261106/README.md)和161项自动测试。验证器不会再次调用远端模型。历史v7的20次实验独立保留，不计入本轮。

## 候选人建议亲自做的三件事

先运行 `python -m scripts.run_tests --output outputs/my-verification`，确认测试确实执行。随后启动 `python -m src.web --port 8810 --open`，在网页选择真实模型并亲自运行以下需求，记录运行 ID。新端口可避免误用仍在运行的旧版服务；真实模型需要自己的登录或 API 环境。

| 实际操作 | 需要解释的观察 |
|---|---|
| 载入“38 秒旧稿修订”，不改输入 | 哪一条工具观察暴露超时？下一步由谁选择？修改后是否重新检查？ |
| 载入“一次故障后恢复”，看执行过程 | 失败出现在哪步？后续动作是否真的读到了失败？是否伪造成功？ |
| 载入“没有产品素材” | 没有素材为什么不直接靠模型常识写？结果中的资料缺口是什么？ |

再看 P01 的公开脚本和审稿备注：两者服务于不同读者。只在备注里写一个产品事实，不能算已经在视频里满足“介绍该功能”的需求。

累计个人投入约4小时（根据聊天与人工测试记录事后估算），已记录在[个人投入与贡献说明](20-personal-contribution.md)。下面是可选的单次复验记录表；累计时间不代表已经完成本页建议的所有操作。只有实际做过后才填写，保持未做事项为空：

```text
本人复验日期：
本次复验实际投入时间（与 AI 自动执行时间分开）：
运行命令或网页场景：
运行 ID / 证据文件：
我观察到的现象：
我能解释的原因及对应代码：
我仍不理解的地方：
本人独立修改（没有则写“无”）：
```

## 六个问题，检查是否真正理解

**为什么这是 Agent？** 模型从当前状态和工具结果中选择检索、改稿、检查或结束；`src/agent.py` 负责执行、保存和限制权限。宿主约束动作合法性，但不是把所有后续动作预先写死。拿一条先失败、后改变动作的真实 Trace 来解释，比只说“用了 ReAct”更有说服力。

**模型说完成就算完成吗？** 不算。当前稿的事实/规则、估时、需求核对都要通过，检查还须绑定当前稿及原始请求。修改稿件会使旧检查失效；最大步数耗尽就明确未完成。验收脚本也需独立拒绝缺失、失败或旧稿的需求核对。

**改写以后怎么核对事实？** v5 新稿把实际文案与来源原句分别保存。宿主先核对本次检索的 source_id/fact_id 并提取原文；语义审核再判断改写、压缩或翻译是否得到该原文支持。不能仅凭真实 ID 就放行新能力或效果承诺。strict 模式和无版本号的旧稿保留逐字核对，便于复算历史证据。语义审核仍使用同一后端，不称为独立事实认证。

**声画时长怎样计算？** 当前创作稿使用format_version=3，按段记录人物动作、说话者与台词。每段时长取配音、屏幕阅读、展示停留、动作最低时间的最大值，各段顺序累计；无对白动作同样计时。同步出现的中英文不直接相加为两段，屏幕上多块文字仍全部计入阅读量。镜头还要满足最低停留，尾部保持时间会显示出来。英语按词、汉字按字估算；没有合成配音或实测成片，所以交付的是预计时长。旧v1/v2稿保留旧算法。

**如何证明测试没造假？** 输入预先冻结，网页提交字段、原始输入、模型调用诊断、Trace、输出、截图及哈希一起保存。Mock 只证明工程行为；真实调用证明实际发生过这条路径；人工阅读才能进一步判断脚本质量。状态 completed 不是质量满分。

**你自己做了什么？** 如实说清题目选择、验收重点、人工试用、范围和迭代决策；代码和自动实验由 AI 辅助执行。能现场说明一个失败案例、定位一条守卫逻辑并完成一个小修改，比背诵“独立实现全部模块”可靠。不要把本页提供的解释当作已经掌握的证据。

## 提交前最后一步

在同一个 GitHub 仓库交付代码、文档和证据，推送最终 commit，确认私有仓库评审账号可读。答题框模板见 `06-submission.md`。本地 ZIP 只是可复核工作区快照，不能代替 GitHub URL 和完整 commit SHA。README 中的操作命令应由候选人至少亲自复验一条。
