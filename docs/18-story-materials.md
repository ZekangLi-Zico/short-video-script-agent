# v7.1 城寨风云编剧资料

原示例只有四条编辑器功能事实，适合验收引用与修订，难以评估人物塑造、情节和对白。本次使用已有《城寨风云》前十二集改编资料，让使用者用熟悉的剧情判断脚本。

## 内容

- 32 张资料卡、129 条剧情/设定信息：故事全貌与规则、12 集剧情、9 张人物关系卡、7 张场景卡、道具承接、创作口径。
- 9 份来源快照，保留原文件名、SHA256 和卡片对应行号；不是重新杜撰一个产品。
- 第六集饭局与审讯、第七集看拳及身份揭晓、第八集送饭与借剑、医院探望等按后续局部修订整理。
- 5 组可直接载入的需求：陈峥人物预告、阿晴送饭、同行者对决预告、医院探望、中篇回顾。需求描述创作场景，不给预制标准答案。

[完整资料正文](../data/packs/city-drama/资料全文.md) · [资料 ZIP（含来源）](../data/packs/city-drama/city-drama-materials.zip) · [五组需求 JSON](../data/packs/city-drama/briefs.json)

## 使用

网页选择“城寨风云 · 前十二集剧情资料”，展开资料可按分类或关键词查找；载入需求后可自由修改主题、受众和时长。选择真实模型并运行，结果和过程仍保存到 `outputs/web/<id>/`。角色对白在网页标为“配音”，角色归属在镜头说明中，下载配音正文不念姓名或制作说明。

CLI 使用请求里的 `product_id: city-drama` 自动选同一资料包；`--materials data/packs/city-drama/materials.json` 也会读取包内规则。原 `demo-editor` 和无资料场景不变。素材编号用于准确检索与溯源，不进入观众台词。

## 改动范围

新增本地资料目录和可读全文；网页接通独立目录；写稿和审核在剧情模式下按故事设定、人物动机和因果理解来源，允许自然改述、对白和镜头设计。沿用原检索—写稿—检查—调整流程，没有新增审核模型调用层数或大批防御规则。

原版本备份位于 `archives/v7-before-story-pack-20261106-011637/`。旧源码、例子和文档有 ZIP 与清单，旧实验及网页记录有哈希清单。没有改动 `D:\姑获鸟` 原工程。

## 验证与边界

验证记录见 [本轮记录](../evaluations/story-pack-20261106/README.md)。140项自动测试通过；另选送饭对白、人物预告两条需求通过网页调用真实模型，草稿、审核和异常诊断均保留，最终状态以记录为准。原 v7 的20次数据单独保留，不能将此次资料扩展描述成20次新实验的质量提升。

本包是现有改编版本的文字资料，不是全书设定库；范围到第十二集“中篇完”。未接入图片、视频、音乐或配音，没有声称这些镜头已经拍成。短视频 Agent 的最多8镜头、300秒输入上限未改变；更长整集分镜需分场创作。模型生成仍需创作者通读，引用通过不等于艺术表现优秀。
