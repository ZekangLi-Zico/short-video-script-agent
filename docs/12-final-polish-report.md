## 做了哪些改进，与原题有什么关系

| 改进 | 原问题与处理 | 对原题的价值 |
|---|---|---|

| 分离审稿备注和视频内容 | 旧 v4 的 V46 将删除无依据宣传的过程说明塞进旁白。新增 `editor_notes`，在网页和 Markdown 单独呈现，不计入时长，不作为来源 | 改进“可编辑脚本”和“有效修正”：创作者能知道删改原因，观众不必听内部审稿过程；公开文案仍检查事实 |
| 明确备注的约束 | 备注可以提及已删除的错误说法，但不能代替应展示的功能或充当证据。修改备注也使旧检查失效，旧格式仍可读 | 保留事实可追溯和当前稿复检，避免为了好看绕过原题约束 |

| 整理评审和个人复验入口 | README 指向五分钟证据路线；历史统计标清版本；提供候选人实际操作与解释的记录模板 | 减少评审核验成本，如实体现 AI 使用、验证和技术取舍。不能保证分数或录用 |

## 还存在什么问题

- **模型审核可能误拒绝或漏判。** P01 对8秒话筒画面的节奏判为 uncertain 并调整；原样重复的 P04 则接受该停留，分别12步/14响应和8步/9响应，表现仍有波动。 同一后端的新上下文审核有相关错误；完成状态只能说明当前检查通过。备注分离的提示也不是机械语义保证，仍需看实际脚本。
- **时长只是估算。** 没有实际配音/成片测量；英文、数字、停顿和中英同时显示的文本可能偏差。0 秒最低停留不等于 0 秒实际镜头，本轮未修改估时算法。
- **语言和创作范围有限。** 逐字事实引用限制改写、翻译和极短文案；方言需人工确认。产品素材仅为合成示例，不能外推为对真实小影产品全面支持。
- **保存不能对抗所有基础设施故障。** 保留 v4 的逐步检查点与清理异常处理；磁盘完全不可写、调用尚未返回就断电，仍无法保证完整响应。没有自动续跑或多用户生产 Runtime。
- **审稿备注可能残留阶段性措辞。** 本轮 P03 最终备注仍有“待本稿重新检查”，而完成状态、Trace 和检查面板已是复检通过。备注是写稿时的解释，不是实时状态字段；该措辞可以人工编辑，暂未增加额外模型调用去同步备注状态。
- **真实 API Key 路径尚未联调。** 有接口契约测试，本轮真实证据来自 Codex CLI；不把它写成所有模型后端都实测通过。
- **本轮定向样本小。** 只补改动相关路径和原题负例，没有再跑 50 次；不据此宣称整体成功率、零幻觉或平均效率提升。

以上可在文档明确后保留，符合原题建议优先完成核心链路的范围。若新实验出现编造产品事实、虚报完成、原题核心路径缺证据，应作为阻塞问题处理，不能只写进限制。
