# 01 · 需求与成功标准

## 当前v7.3.1范围

保留原题的产品脚本入口和三项业务工具，以及v7.3的动作、说话者和无对白动作编排。本次只修复证据版本复算并统一提交材料；当前真实验收入口为[examples/current](../examples/current/evaluation.md)，本轮结果见[提交复核报告](../evaluations/submission-v7.3.1-20261106/README.md)。

## 历史v7更新

v7在原题范围内提升文案自然度与逻辑连贯性；先连续讲述再分镜。原有来源、预计时长、缺信息和失败处理保留。见[v7实际报告](17-v7-natural-voice.md)。

历史v6继承有依据的改写/翻译、旁白与屏幕节拍、具体分镜编排，并优化场景标题与模型调用效率，见 [效果报告](16-v6-titles-latency.md)。原题范围保持不变；检查点、备注和网页均是交付辅助，不是新增的生产级要求。

## 用户与目标

服务需要快速起草短视频脚本的创作者。输入主题、受众、平台、目标时长和风格，结合产品资料与品牌规则输出有事实依据、满足预计时长上限的可编辑脚本。资料不足时明确指出缺口；不编造卖点或伪称完成。

## 输入与材料

- 六项必填：`topic`、`audience`、`platform`、`target_seconds`、`style`、`product_id`。
- 可选 `initial_script` 检查旧稿；`expression_mode=strict|creative`；`duration_mode=max|target`。缺省strict/max兼容旧输入，网页新任务默认creative/max。
- `data/materials.json`：合成资料，带产品 ID、素材 ID、事实 ID、版本日期与事实原文。
- `data/brand_rules.json`：允许的连接语/标题/画面指令、禁用表达、语速估算参数。
- `data/packs/city-drama/`：按既有改编文本整理的漫剧扩展资料；原题产品入口仍保留。

## 范围

实现 CLI、三个本地工具、单 Agent 动态决策循环、真实模型适配器与离线 Mock、测试和运行记录。按用户追加需求提供本地网页，便于填写输入、查看实际执行过程与下载结果；网页不改变题目验收标准。不包含线上部署、多 Agent、视频生成或发布。

## 验收映射

| 题目要求 | 实现 | 运行证据/测试 |
|---|---|---|
| 正常生成 | 检索→生成→检查→结束，顺序由模型选择 | `normal`；`test_valid_completion_and_saved_artifacts` |
| 缺关键信息 | 输入校验返回 needs_input，列出缺失字段 | `missing_information` |
| 无素材 | 模型观察空检索后补查或请求补充 | `no_material` |
| 工具失败 | 错误返回模型；模型选择重试或停止 | `tool_failure`、`recoverable_failure` |
| 超时修订或明确失败 | 绑定原时长上限，修改后复检 | `over_duration`、`impossible_duration` |
| 规则不通过后调整 | 展示风险位置，模型替换无依据文案，再检查 | `rule_revision` |
| 标题、分镜、旁白/字幕、总时长 | `output.json` 与 `script.md` | 正常输出及超时修订输出 |
| 来源 ID、风险、任务状态 | 事实块、citations、issues、status | 规则检查及来源测试 |
| 至少两条动态路径 | 真模型实际观察不同工具结果后调整 | `examples/live/` 的 Trace |
| 至少三组输入、输出、运行记录 | 八种场景分目录保存 | `examples/mock/` 与 `examples/live/` |
| 执行上限 | 12 步默认上限，超限 step_limit | 提前完成/未知动作/上限测试 |

## 成功标准与边界

`completed` 必须满足当前脚本结构合法，至少有一条来源事实，所有公开文案通过规则检查，预计总时长不超过上限，检查哈希与当前稿一致。修复版增加需求覆盖核对：同后端模型用新上下文逐项评估原始主题、受众、平台、风格；未满足、不确定、检查失败或未检查都不能标记完成。三项检查绑定当前稿，需求核对另绑定完整原始输入。来源、产品、目标上限都由宿主绑定，模型不能改检查参数绕过约束。

需求覆盖核对是对原题“按输入生成脚本、无法满足时说明”的工程补强，并非原题强制指定的第四个工具。宿主验证核对结构和绑定关系，不宣称确定性证明语义正确。有限修复及新增证据见 `docs/08-limited-repair-report.md`、`examples/repairs/`。

场景验收的成功不等于业务任务均应 completed。例如无素材预期为 needs_input/blocked，工具持续失败预期为 blocked/step_limit，不能把失败场景强行包装成成功。

可以选择“上限”或“接近目标（90%–100%）”。当前v3格式按段安排动作和声画，重叠时取较长时间，前后段依次累加；历史v1/v2保留对应算法。创作模式的标题、画面、动作和全部文案接受语义审核，包括带来源的改写；原文与来源身份由本地工具验证。漏项、无依据声明、不确定与审核失败不能完成。旧稿和strict模式继续逐字核对。输入缺失由前置校验处理，不宣传为模型自主追问。

历史v3与v5优化见 `09-quality-v3-report.md` 和 `15-v5-effective-scripts.md`；当前版本以本页顶部入口为准。固定旧白名单仍可复现，但不限制创作模式的生活场景和标题。
