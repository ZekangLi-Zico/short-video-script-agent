## 1. 修复了什么

旧验证器用当前检索算法复算所有历史记录。早期超时案例查询含P01，当时的关键词检索返回P01、P02、P03；v7.1增加精确ID优先后只返回P01，导致该步结果以及后续已检索ID集合不一致。上轮[问题复核](../requirements-audit-v7.3-20261106/README.md)保留原失败结论。

现在：

- 新运行及检查点保存 `tool_contracts.search_materials=id_first_v2`，清单和输出记录对应的契约。
- 未标应用版本的原始记录及v7使用历史 `keyword_v1`；v7.1–v7.3按已知版本映射到ID优先检索。兼容算法依据现有Git历史e624c5a的实现，仅用于复算，不改变当前运行工具。
- 验证器按声明/版本选择算法，不根据保存结果尝试哪种算法能过关。未知契约、版本冲突、缺失文件及被修改的观察仍会失败。
- 默认验证当前 `examples/current/` 和历史 `examples/mock/`、`examples/live/`；支持按组、按目录选择。新报告默认放入 `outputs/evidence-audit/` 的时间戳文件，原 `examples/evidence-audit.json` 不覆盖。

新增6项回归覆盖原问题、篡改拒绝、不同版本查询差异、新记录契约、命令行报告保存和缺文件失败。修复前[完整失败日志](regression-red-complete.txt)为1失败、4错误、1通过，修复后[6项全部通过](regression-green.txt)，[完整161项测试](automated/summary.json)通过。最初一次测试执行因默认临时目录清理受阻而中止，原日志 `regression-red.txt` 保留；后续测试使用项目内临时目录，完整结果以前述日志为准。

### 实际脚本阅读

产品稿按“展示已有录像→添加字幕→修改咖啡名→确认结果”推进，台词给出“耶加雪飞”改为“耶加雪菲”的示例，动作与说话者有对应时间。公开软件能力只包含素材支持的添加字幕、手动编辑文字；具体咖啡名称是场景示例。作为合成产品资料的教学脚本可供人工试读，不代表已有真实软件录屏。

超时旧稿保留两句原文，主要去掉冗长停留，最终7.3秒满足本次“上限30秒”。它证明模型观察超时后实际调整并复检，不证明形成了接近30秒的完整广告，也不把压得更短视为普遍质量提升。当前动作/对白自然度继续以实际稿件和人工判断为准。

## 5. 原题要求与仍有的边界

当前版已具备原题输入、三项本地工具、模型动作循环、12步上限、可编辑脚本、来源与风险、异常状态、运行命令和文档。当前四条记录证明正常、超时修订、空检索、工具故障四种实际模型路径；缺必填是宿主前置校验，另有当前自动测试和历史原始记录。至少三组输入/输出/Trace已在examples内，本次没有把离线测试冒充模型决策。

保留事项：

- 时长为文本与动作估算，尚未做TTS或成片测量；这不是原题要求的真实视频交付。
- 超时案例从旧格式转换为v3，修订统计按完整结构块比较，显示0个块完全保留，但两句台词文字实际未变。本次未扩展修改这项显示口径。
- 模型仍可能写出需要人工修改的内容；当前四类验收不能代表所有题材、所有模型或生产可靠性。本轮没有针对这些边界再加拦截规则。

## 6. 提交GitHub前需要用户提供

目前本机没有Git远程，也未配置提交姓名和邮箱，见[配置状态](git-readiness.json)。需要：

1. **仓库URL**；若需新建，提供所属个人/组织与仓库名。
2. **公开或私有**；选择私有时，提供笔试方指定评审的GitHub用户名以授予读取权限。
3. **Git提交署名与邮箱**，可使用GitHub的noreply邮箱。
4. **本人实际投入时间与实际工作记录**：亲自阅读、测试、修改过哪些内容，以及哪些由AI辅助完成。本人时间不能用本轮自动运行时间代填。

无需提供密码、API Key或登录令牌。最终SHA应在真实提交并推送后读取，不需要用户预先填写。拿到上述信息后，还需核对最终提交文件、干净检出的可运行性、远程内容及权限，再生成答题框里的实际URL和完整SHA；本次未创建远程仓库、推送或交卷。
