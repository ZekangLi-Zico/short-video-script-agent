## 最明确的改善：视频内容与审稿说明分离

**V46 宣传旧稿纠错。** 旧版最终第三镜会朗读“旧稿第二镜……缺少数据……已删除”的内部修改说明。新版公开稿只有两镜：添加字幕、手动编辑文字；自动识别及 99% 准确率说法被删除，依据不足、删除不等于产品不支持、如何补证等解释完整放入 `editor_notes`。网页和 Markdown 均将它单独显示，不计入视频时长，也不充当事实来源。

|同一需求|v4|v4.1|
|---|---|---|
|V46 旧稿纠错|3 镜，21 秒；内部说明进入旁白|2 镜，12 秒；说明只在审稿备注|
|V36 口头反馈称播放量提高 30%|4 镜，17.3 秒；最后一镜朗读证据与授权提醒|3 镜，13.5 秒；风险解释单独放入备注|

两例都保留了有来源的基础字幕功能，没有将未经验证的效果当成事实。V46 两轮同为 **12 步、14 响应**；新版也先拒绝静态话筒停留 8 秒的节奏，再改为 4 秒并复检。这里的改善是交付内容更适合创作者使用，不是模型调用变快，也不是取消审核。参见 [V46 新稿](runs/V46/script.md)、[旧稿](../realistic-50-v4-20261104/runs/V46/script.md)、[V46 Trace](runs/V46/trace.jsonl)、[V36 新稿](runs/V36/script.md)。

**V31 八字卡片找到了可执行呈现。** 旧版认为完整事实超过八字，直接请求短原文。新版保留完整 P02 引用，同时在画面说明中分成“剪影练习版”（5 个汉字）与“支持裁剪视频片段”（8 个汉字）两卡，各展示 5 秒，无旁白，只有剪刀与纸片意象。按输入的“每张卡最多 8 个汉字”检查，方案满足字数和 20 秒上限。

这次改善不能归因于新增备注字段这一单一原因：模型随机性也可能影响选择，而且卡片拆分仍只写在 `visual`/备注中，没有独立结构化卡片对象。制作者必须按说明执行，门店远距离可读性需现场验证。参见 [V31](runs/V31/script.md)。

## 仍然存在的问题

1. **备注不是实时状态。** 37 份带稿件的结果中，17 份备注留有“待估时”“待重新检查”或时长状态含混措辞，涉及 V02/V03/V07/V09/V11/V14/V15/V16/V19/V21/V25/V29/V30/V32/V45/V47/V49；其中 16 条最终 completed、1 条 needs_input。它们的实际检查记录存在，不是 17 次检查没执行。V11 等措辞也可能指成片实测，仍不够清楚。建议人工清理交付文案，后续若修复代码，应让备注只记录修改事实，最终检查状态继续由实际结果显示，避免额外模型调用制造新不一致。
2. **翻译和极短表达仍有限。** V22 中文旁白配英文事实翻译仍未生成；V30 三功能八秒稿实际估时 12.8 秒后停止。这不能简单归为“完全没资料”，也不证明真实剪辑中绝无方案；是当前逐字引用、不可拆分事实块与串行估时的策略边界。V31 的成功也没有普遍解决这类问题。
3. **英文受众的可理解性需人工确认。** V21 英文旁白主要描述场景，产品事实由中文静默卡与画面示意承载。形式上得到审核放行，但纯英语观众是否理解两项功能仍是疑点。不能只展示 completed 而不展示正文。
4. **时长仍是估算。** 字幕、静默事实卡、旁白有时同步、有时串行，结构中没有完备的独立时间轨。V06/V08/V12/V17/V21/V28 等需实际试读、阅读测试与剪辑复核。90%–100%接近目标区间是项目约定，不是原题硬规定。
5. **创作质量不稳定。** V05/V17 增加了有依据但未明确要求的手动改字内容；输入没有禁止，所以记为范围扩写而非事实编造。V48 后两镜“先看看招牌”“再看看室内”满足约束但普通。V01/V50 同输入分别估时 17 与 13.1 秒，稿件不同、约束都保留；一对重复不足以证明总体稳定。
6. **审核仍可能误判或漏判。** 本轮逐稿评阅未发现明确的无依据产品事实被作为最终事实放行，也未发现伪造完成记录，但不是独立盲评或零幻觉保证。V21 的表达疑点、17 份备注问题均保留，不用状态覆盖内容判断。
7. **原题完整验收仍需既有专项证据。** 本轮没有刻意清空必填字段，也没有注入业务工具失败；缺信息、持续工具失败与一次失败后恢复应结合当前版本的 [P05/P07/P08 定向实验](../final-polish-20261104/README.md)，不能声称这 50 条独自覆盖所有验收项。API Key 后端未实际联调，多用户生产运行和视频生成仍不在本次范围。

## 对原笔试的意义与当前结论

本轮补充的是可核验的工程与内容证据：模型根据失败观察有效修订；产品事实可追溯；视频正文与审稿解释分工清楚；自然清理异常没有吞掉响应；不把未完成伪装成成功。它们直接对应原题的动态决策、有效修正、事实可追溯和“用测试证明效果”，不等于招聘方已经给分。

**当前有依据说交付质量有所改善，尤其 V36/V46；没有依据说全面解决了创作质量或显著提高成功率、降低成本。** 本轮未发现需要立即修改应用才能继续提交的新增明确阻塞缺陷，但提交前应人工读完要展示的稿件、清理展示稿中的过时备注，并如实说明双语、估时、审核和资料边界。若后续发现编造事实或虚报完成，仍应视为必须修复。

本轮不改代码，保留原项目 ZIP、所有旧版本与旧实验；新增完整复测提交快照并更新 README、评估与提交说明。最终 GitHub URL、已推送的 commit SHA、评审权限，以及候选人的真实投入和亲自复验记录仍需补齐；没有代为推送或交卷。
