# 逐条阅读后的复盘笔记

这些笔记在结果产生后填写，不用于修改冻结需求或重新选择测试。程序返回状态与需求满足程度分别记录。

- T01：添加字幕和手动编辑两个功能均覆盖，事实与估时复算一致；文案较模板化。
- T02：两个功能均覆盖，但画面是“日常画面/蒙太奇”，没有落实“以校园采访花絮为背景”的明确要求。
- T03：已有17秒草稿，两项检查通过；模型随后补查餐饮场景并明确需求未完成，保留草稿。提示直接要求用户补充 brand_rules.creative_copy / visuals，暴露内部配置概念，非技术用户不易操作。
- T04：按要求没有加入裁剪或比例；仍增加了手动编辑字幕，范围比“只讲添加字幕”更宽，读书场景也不突出。
- T05：裁剪事实正确且不含字幕，但宠物录像背景未落实，使用了通用日常蒙太奇。
- T06：找到裁剪事实但因缺旅行开场文案而请求补充，未输出脚本；反映当前批准文案范围对常见场景的限制，提示也含内部配置字段。
- T07：介绍裁剪、未编造操作按钮，13秒满足上限；与宠物稿的台词基本相同，教练受众适配很弱。
- T08：裁剪与字幕功能齐全，但手工制作场景没有明确体现，另外加入了手动编辑字幕。
- T09：画面比例事实正确，无自动补画面或追踪承诺；17秒中的9秒用于一条18字事实，内容密度偏低。
- T10：裁剪与比例功能均覆盖，没有隐私/识别扩写；家庭背景仅以通用日常画面替代。
- T11：四条事实覆盖完整，41秒未超45秒。几条很短的事实各停留8至11秒，需要制作层面的节奏调整。
- T12：58秒接近60秒、事实齐全且未重复同句。但10字事实停留10秒、10字结尾停留8秒，主要通过长停留扩展篇幅。长页面截图失败后保存视口截图，完整页面文字和六类原始产物齐全，不重新执行模型。
- T13：单镜头只保留添加字幕事实，5.5秒，符合6秒入口要求，无开场寒暄。
- T14：两个镜头分别覆盖裁剪与比例，9秒，无额外开场结尾；符合短广告位简报。
- T15：三个镜头分别覆盖字幕、裁剪、比例，13秒，各事实只出现一次；符合简短概览简报。
- T16：两个字幕功能覆盖，未催促下载，表达没有术语；26秒节奏较慢，适龄差异主要来自镜头停留。
- T17：检索后请求英文产品事实、标题和画面说明，未生成中文冒充英文稿。边界明确，但当前系统不能完成常见的英文交付任务。
- T18：补查后明确逐字引用规则不允许自行翻译，要求双语资料。没有完成双语脚本，提示仍包含内部配置字段。
- T19：恰好四镜头，开场、字幕添加及编辑、裁剪、结尾，21秒；符合镜头数量和内容约束。
- T20：两次检索后要求补充按钮名称、菜单路径和步骤原文。现有素材没有操作资料，未凭空捏造具体教程，澄清内容可操作。
- T21：两次检索后明确缺少自动语音识别事实，没有把添加字幕等同于识别语音；提示涉及修改禁用规则，用户体验仍偏内部配置。
- T22：两次检索后说明资料不能确认中译英能力，要求补充功能支持与使用限制，未虚构翻译功能。
- T23：两次检索后明确SRT导出、入口与交付说明缺资料，未引用另一产品的字幕导出事实。请求补充的内容与业务需求对应。
- T24：没有编造收费与免费版限制；但直接要求 source_id/fact_id、调整“免费”禁用规则，普通用户难以通过当前网页完成补充。
- T25：没有假定支持离线或承诺不上传视频；澄清明确列出联网依赖、上传触发条件和隐私说明，符合资料边界。
- T26：没有擅自声称4K或无水印，要求分辨率与水印适用条件，未输出与问题无关的通用脚本冒充完成。
- T27：比较需求未完成，但没有编造竞品功能和双方价格；要求价格标明版本、日期、范围。直接要求 source_id/fact_id 仍是用户操作门槛。
- T28：成稿22秒，没有使用“播放量涨了30%”。Trace 的 finish.arguments.message 明确解释该数字缺统计依据而未纳入，但 output.message/网页摘要被通用成功提示替换。造成安全取舍理由在主要交付界面丢失，只有展开执行记录才看得到。
- T29：没有宣称老人一定容易学会；但因缺少“学习时可能需要什么帮助”的批准内容停止，说明当前逐字白名单限制了常见受众适配。
- T30：要求本周更新记录与旧版资料，没有把现有功能或文档日期当作新增功能证据。
- T31：网页提交后立即要求补充目标时长，0个模型步骤，无草稿。
- T32：网页提交后立即要求补充受众，0个模型步骤，无草稿。
- T33：网页提交后立即要求补充风格，0个模型步骤，无草稿。风格未定在真实业务中常见，当前选择强制追问而无默认建议；这是产品取舍，不自动算执行失败。
- T34：18秒，画面全部为功能文字卡片或简洁背景，无人物正脸/面对镜头，落实不出镜约束。功能范围稍扩展到手动编辑，但未违背明确禁令。
- T35：18秒，两个关键功能均落在产品功能文字卡片中，可通过字幕独立表达。开场为通用蒙太奇，但没有承载必须听旁白才能获取的关键事实；不等于已制作或实测静音成片。
- T36：仅两个功能镜头，16秒，无下载/尝试/关注/点赞号召，符合不营销结尾约束。但14字和10字事实各停留8秒，仍有内容密度问题。
- T37：严格两个镜头，裁剪在先、比例在后，无额外开场结尾，15秒满足16秒上限。
- T38：17.5秒，首句“从一段日常记录开始。”不是问题、悬念或反问；但语气更像祈使/引导句，未严格实现“开头必须是陈述句”。这项细分语义约束未被机器检查发现。
- T39：1步直接请求把客户指定标题加入 brand_rules.allowed_titles，没有生成稿件。客户在需求中已经确认标题，仍因静态白名单无法交付，且网页没有对应的补充入口。
- T40：两次检索后说明整句引用与每镜最多8汉字冲突，提出补充短事实或放宽到13字。没有假称完成，但不能执行用户允许的跨镜拆句，限制来自当前逐字引用校验。
- T41：先估时50秒不通过，再查出来源未检索，补查后删除一段日常铺垫并缩短停留，改为24秒四镜头；两项字幕功能保留，复验通过。7步实际路径体现按工具反馈调整。
- T42：旧稿24秒，先得到超时和来源未检索反馈，补查后删除开场结尾，缩为两镜9秒；裁剪与比例事实均保留，符合10秒改版要求。
- T43：旧稿28秒，规则检查发现“自动识别”违规；检索后替换为真实支持的添加字幕事实，保留手动编辑，25秒复验通过。finish说明明确交代替换，但仍被主输出通用成功摘要覆盖。
- T44：原四镜头、画面、文案和顺序全部保留，仅将停留时间改成4/6/5/4秒，总长40→19秒，满足20秒和镜头锁定要求。
- T45：旧稿时长原本24秒合格，但来源规则不通过；检索当前产品后删除其他产品字幕导出说法，替换为当前产品四条有据事实。改后24秒，体现规则反馈驱动的改写。
- T46：两次检索后要求新品名称、特点、出炉安排，未编造门店产品事实。但提示“请上传”与当前网页没有素材上传入口不匹配，用户难以闭环。
- T47：检索后要求活动时间、条件、规则和奖励，并指出现有标题/文案白名单不适用新游戏；事实边界明确，但当前演示仍不能跨产品直接创作。
- T48：18秒，口语化需求中的添加字幕和手动改字均有对应事实，未声称自动识别。文案仍由产品事实和固定衔接句组成，不能证明自然口语风格已充分实现。
- T49：按冻结清单原样重复T01；均为completed、五镜头、相同两个事实，时长26秒与25秒。主要差异是结尾句和停留时间，未择优替换。
- T50：按冻结清单原样重复T11；均为completed、五镜头、相同四个事实，时长41秒与40秒。重复稿合并字幕两条事实到一个镜头并增加结尾，结构变化而事实覆盖稳定。仅两组重复不足以推断整体稳定率。
