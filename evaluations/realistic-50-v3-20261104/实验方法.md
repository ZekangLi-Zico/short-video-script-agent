# 实验方法与记录边界

本轮按用户要求，使用网页实际提交需求、调用已登录的 Codex CLI 真实模型。没有使用 Mock 输出替代实验，没有通过网页的预设场景或“应该看到什么”构造输入，没有人工注入工具故障。测试时间按北京时间计为 2026-11-04；机器文件的 ISO 时间采用 UTC。

## 输入如何形成

先按运营、门店、社团、创作者等工作情境写好全部输入，冻结为 `cases.json`，再开始第一条运行。冻结摘要为 `d173710d0f93a63744584cd839b4070c70f8f748022721b200b51d50fb9fe1a3`。每次在网页选择“自定义需求”，填写原文、受众、平台、风格、时长要求和旧稿，再核对页面值。

这里的“真实”指实际在线模型调用和真实网页链路。需求是贴近工作情境的合成 brief，产品资料也是题目允许的合成资料，并非真实客户交付或小影公司的产品事实。场景涉及的其他平台名称只是需求背景，不代表本项目接入了其接口。

共计划 50 次实验、49 份不同输入；V50 是预先安排的 V01 原样重复，用于观察一次重复运行的表现。部分需求类型与历史测试重合，不声称是完全未见过的独立测试集。输入没有预期状态或预定工具路径；运行后按原始 brief 评阅，不能为了通过而改写需求。

## 执行条件

所有输入都通过网页提交；没有通过 HTTP 脚本绕过页面直接发起运行。四个同版本本地服务最初交错执行，发生 Windows 临时目录文件占用异常后，仅保留两个实例接续。变更见 `protocol-amendment-01.md`。这是实验负载变化，不足以证明并发是异常根因，耗时也不能当作单用户生产性能基准。

运行中的业务工具使用题目允许的本地函数，模型决策和需求审核调用真实 Codex。模型元数据中的 `CLI configured default` 表示继承当时 CLI 默认配置；不能据此独立证明远端具体模型版本。Trace 保留实际返回的 provider、thread_id 和 usage 等元数据。

V43 有一次首次模型响应前的失败，完整保存在 `attempts/V43-no-response-01/`，不计入 50 次有模型响应的实验。同一冻结输入另行重试。同期共享 CLI 诊断出现 `Selected model is at capacity`；该文件不是逐任务隔离日志，不能据它为其他调用失败统一归因。已产生真实响应的中途失败仍计入 50 次，不用重跑成功覆盖。

## 每次保留什么

- `brief.json`：冻结情境与输入；`ui-input.json`、`before.txt`、`submitted.txt`：实际网页输入和提交状态。
- 常规结束：原样复制后端的 `input.json`、`output.json`、`trace.jsonl`、`manifest.json`、`data_snapshot.json`、`script.md`。
- `after.txt`、`ui-record.json`、`page.jpg`：网页最终状态；`review.json`：开发助手依据原始需求及真实输出写下的评阅。
- V04、V05、V09 在临时目录清理异常后没有保存常规后端产物，单独保存 `partial-output.json`、`partial-trace-ui.json` 及 `infrastructure-error.json`。这些是页面可见部分证据，不是补造的完整 Trace 或 manifest。
- 三次部分记录只给可确认的模型响应下限，不能虚构准确响应总数或 token 总量。

`results.csv` 记录程序状态；`逐条复盘.csv` 记录需求层面的评阅。两者分开：`completed` 不自动等于业务合格，`needs_input` 也不自动算失败或正确。具体原因须回到原始需求和记录中检查。

## 复核及复现

开发助手逐稿核对事实、排他范围、受众和场景、估时、修订及停止理由。这不是独立盲评，也没有真实配音、拍摄、剪辑成片或目标用户可用性研究。生成内容里的秒数是估算值。

现有 `scripts/verify_evidence.py` 对保存的结果作确定性复算，检查记录一致性；它既不调用 Mock 替代真实实验，也不证明所有语义判断都正确。`validation.json` 核对冻结输入、网页输入、真实模型元数据、后端文件副本、旧证据哈希以及 v3 原交付 ZIP 中的代码/数据哈希。

`prepare-campaign.py` 是开始测试时工作区 `.runtime/prepare_v3_real50.py` 的原样参考副本，使用相对项目根目录的定位逻辑；不要在当前目录直接执行，也不要再次运行它覆盖冻结实验。`ui-harness-reference.js` 是当时 CUA 网页操作函数参考，依赖既有浏览器绑定和调度状态，不是可直接在 Node 中运行的脚本。完整实验的复现需要原项目、已登录的真实模型服务、相同资料、依次填写冻结输入；模型输出未必逐字相同。

`method-reference/` 同样保留工作区 `.runtime/` 下审计与打包脚本的原样参考副本，原始路径定位逻辑没有改写；在实验包内直接运行这些副本并不等价于在完整项目中复核。可独立执行 `python verify_bundle.py` 核对本实验包已有文件的 SHA-256；它不进行新实验、不访问网络，也不证明模型答案正确。

V03、V49 的浏览器自动化操作曾在正式提交前中断，均先读取网页确认未启动新任务，再继续同一冻结输入；对应 `ui-interruption.txt` 保留现场说明。V49 在同一浏览器新标签页恢复，重新展开旧稿区并核对完整输入后才提交。这些操作中断没有用来增加模型实验计数。

本轮不修改 Agent 实现，不覆盖旧版本、原始 50 次测试或 v3 提交包。新实验的结果作为独立补充材料保存，不能用本轮状态分布与旧实验直接计算提升百分比。
