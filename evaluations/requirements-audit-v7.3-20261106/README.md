## 提交前必须收尾

### 1. 修整历史复算入口的版本兼容

README推荐 `python -m scripts.verify_evidence`。其中 `examples/live/over_duration` 的第3步查询为 `demo-editor 剪影练习版 字幕功能 P01`：历史检索返回P01、P02、P03；当前精确ID检索优先，只返回P01。随后第6步的已检索ID集合也因此不一致。当前验证器会报两项错误。

这是旧证据与新检索逻辑的兼容问题；不能据此说历史38秒→25秒的改稿过程未发生，也不能继续宣传该入口当前全部通过。应保留原始记录，按记录对应版本复算，或让当前验收与历史归档的验证入口明确区分，并展示真实结果。不要修改旧Trace来迎合新算法。本次未进行该修复。

### 2. 完成真实GitHub交付

创建/配置实际仓库、纳入本次版本代码和选定证据、形成最终commit并推送，然后填写题号4、仓库URL和完整SHA；私有仓库需要指定评审账号可读。当前HEAD不是v7.3最终交付。旧v7 ZIP也不包含v7.3，不能代替当前仓库。

### 3. 填本人实际投入并统一当前说明

候选人的实际用时目前未量化；AI辅助范围已经披露，但本人实际读过、修改过、测试过什么仍应据实填写。docs/01、README评审主入口和docs/06答题模板应让评审首先看到当前版，再查看明确标注的历史实验，避免把v7的20次实验、133项测试与v7.3的155项测试混成一次结果。

- 用最终v7.3做一组小型真实模型回归：原题产品正常稿、超时后修订、空检索、工具失败，并按实际结果补入examples。当前4条v7.3真实记录都是正常路径，历史记录和当前离线测试不能直接替代最新模型格式的所有分支实测。无需再机械重复50次。
