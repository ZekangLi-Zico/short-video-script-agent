# v7.3：把动作、画面和对白排到同一时间线上

用户指出旧分镜看起来只有对白，“同拍声画同步”等表达也不直观。本轮将创作模式新稿改为三列表格：**时间（镜内）／动作与画面／对白与声音**。模型按段编排人物动作、反应和说话者；网页与下载脚本共同使用这份编排。

## 实际改动

- 每个时间段写清人物做什么，必要时补充镜头变化与现场声。对白单独标明人物，动作不再只放在整镜概述里。
- 支持没有对白的动作段，例如接电话、掏枪、落子。这些动作有自己的估计时长。动作和对白同时进行时取两者较长的时间，不重复相加。
- 配音文本只导出实际台词，不把人物名字、动作或摄影说明念出来。
- 动作随完整稿进入原有审核；动作修改后旧审核不能继续作为当前稿的通过依据。没有新增一轮模型审核调用。
- 移除“同拍声画同步”；只有实际存在屏幕文字时才提示保留文字。旧稿继续展示原有整镜动作说明，不为历史记录补造新动作。

创作模式使用脚本格式v3，严格引用模式继续使用v2。实现见 `src/schema.py`、`src/timing.py`、`src/staging.py`、`src/providers.py`、`src/reporting.py` 及网页；详细方案见[设计说明](../../docs/superpowers/specs/2026-11-06-staging-design.md)。

两条需求分别选择“不超过30秒”和“不超过45秒”，并非接近目标时长模式。各产生5次真实模型响应，本轮共10次响应、0次超时，时长、规则、需求核对均通过。独立证据复算均无错误，见[机器结果](live-results.json)。这是2条针对本次改动的实际验证，不是重做20或50条实验。

### 楼道片段的同需求对比

新稿与用户此前运行 `3e1b065fee9f4370bd9a3b10feaf49d3` 使用同一需求、同一资料哈希。

| 项目 | 原v7.2结果 | 新v7.3结果 |
|---|---|---|
| 动作安排 | 有整镜画面概述，未与每段对白绑定 | 8段动作按时间与对白对应 |
| 说话者 | 7段台词没有独立说话者字段，需结合概述辨认 | 6段台词全部明确标注人物 |
| 无对白动作 | 未单独结构化编排 | 铃声响后接电话、掏枪并切黑，各占明确时间 |
| 分镜与预计长度 | 5镜、26秒 | 4镜、18.4秒 |
| 生成耗时 | 457.03秒，10次调用尝试中有1次超时 | 181.76秒，5次尝试无超时 |

实际阅读可见，前段“听出乡音后松肩、靠近”到后段“听到劫匪身份后笑容僵住、目光追向掏枪的手”形成连续的情绪转折。动作与对白的对应关系可以直接用于讨论分镜和剪辑，减少从整镜概述自行猜测的工作。新稿是重新创作，台词与镜头数量并不要求和旧稿完全相同；更短也不自动代表更好。本次等待时间下降还受旧次超时、调用数量和模型波动影响，不能据单个对照推断普遍加速。

### 下棋片段的实际阅读

新稿先写徐承岳伸手拿棋时牵动腹伤，再由祖父发问；谈到上台代价时，棋子悬在棋盘上；结尾落子后说“既上拳台，生死无怨”。这些动作参与表达人物态度，镜间状态也有衔接。没有对应旧稿，因此只记录实际结果，不虚构前后提升分数。

## 与原笔试目标的关系及仍有的限制

本次直接改善“可编辑脚本”和“分镜、旁白、预计总时长”的交付质量：人物动作、对白、来源与时间可以逐段检查；单Agent观察工具结果后决策的循环保持不变。

本轮没有重新跑全套真实模型负向验收，缺信息、无素材、工具失败、超时修订等历史证据仍按原版本标签保留，当前自动测试覆盖相关宿主行为。现有资料和模型仍可能写出不够自然、需要导演调整的动作；此次两条结果只能说明这两种实际创作需求已得到有效编排。v1/v2历史稿保留原有信息，要获得逐段动作需重新生成。预计时长属于脚本工具估算，不能当作已经完成口型同步、配音或视频制作。
